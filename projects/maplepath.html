FULL-STACK WEB APPLICATION

MaplePath

Turning the Canadian immigration process into a personalized journey.

MaplePath is a web platform designed to help people understand, organize, and track their Canadian permanent residence journey through personalized roadmaps and community timeline data.

THE PROBLEM

Immigration can feel complicated.

The Canadian immigration process can involve different programs, requirements, documents, applications, and timelines.

For someone going through the process, understanding what they need to do next can be difficult.

I wanted to explore whether software could make that experience more understandable and organized.

THE DEVELOPMENT JOURNEY

Building MaplePath taught me more than code.

MaplePath started as an idea and gradually became a much more complex full-stack application. Along the way, I had to learn how to design systems, debug problems, and make decisions about how different parts of the application should work together.

01

SYSTEM DESIGN

Turning an idea into a system

One of the first challenges was figuring out how MaplePath should actually work. Instead of building isolated pages, I had to think about users, pathways, journeys, progress, timelines, and how all of those pieces connect.

Architecture Data Flow UX
02

BACKEND

Learning to build a real backend

MaplePath pushed me beyond simple frontend websites. I had to learn how APIs, routes, databases, models, and server-side logic work together to create a functioning application.

Node.js Express REST APIs
03

DATABASES

Working with real data

Storing user information, journey progress, timeline records, and community averages introduced a completely different level of complexity compared with static websites.

MongoDB Mongoose Data Modeling
04

DEBUGGING

Learning how to solve problems

Some of the most valuable lessons came from things that didn't work. Debugging backend routes, database queries, frontend logic, and data flow taught me how to investigate problems instead of simply trying random fixes.

Debugging Testing Problem Solving
05

SCALABILITY

Designing for something bigger

As MaplePath grew, I realized that writing code that works is only part of development. The project also needs to be organized so that new pathways, features, and users can be added without rebuilding everything.

Modularity Scalability Maintainability
